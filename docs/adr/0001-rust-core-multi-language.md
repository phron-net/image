# 0001. One Rust core, a binding per language, one repository

Status: accepted, 2026-11-12.

## Context

The Phron Image SDK builds and signs image URLs. The server verifies a signature byte for byte, so
every language must produce the same string for the same input. A second implementation per
language means a second place for a signing bug.

## Decision

- **One repository for every language.** `phron-net/image` holds the whole SDK. Packages are named
  per product: npm `@phron/image`, PyPI `phron-image`, Go under `github.com/phron-net/image/go`,
  crates.io `phron-image`.
- **Rust is the single implementation.** `crates/phron-image` has the options, path encoding,
  signing and URL grammar. It does no I/O. Each language gets it through a binding:
  `bindings/node` (napi-rs) now; Python (pyo3, maturin) and Go later.
- **Conformance vectors.** `conformance/vectors.json` is generated by `conformance/generate.mjs`
  from an implementation that shares no code with the SDK (`node:crypto`, `encodeURIComponent`).
  The Rust test and every binding's test run it.
- **Releases with Sampo.** One changeset per change; `sampo release` bumps `@phron/image` and its
  CHANGELOG; the workflow tags `v<version>`; the tag runs the build matrix and the npm publish.
  See `PUBLISHING.md`.

## Consequences

- The Node package needs a native binary per platform (seven platform packages, optional
  dependencies of `@phron/image`). A platform outside that list cannot install it.
- **Edge runtimes and browsers are not served by the addon.** The earlier pure-TypeScript package
  ran on Cloudflare Workers, Vercel Edge and Deno Deploy through Web Crypto; the addon does not.
  The one browser-side entry, the Next.js `publicLoader`, is plain TypeScript, pinned to the core
  by the `public` conformance vectors. This is a known gap: the intended fix is a WebAssembly
  build of the same Rust core (wasm-bindgen) as a second target of `@phron/image`, which then
  also retires the loader's own URL builder. Nothing has been published, so no user lost anything.
- `signUrl` is synchronous (it was async over Web Crypto), and the `./node` subpath is gone.
